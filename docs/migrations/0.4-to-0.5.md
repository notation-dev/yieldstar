# Migrating from 0.4 to 0.5

Yieldstar 0.5 removes the remaining Bun runtime coupling and supports the resident-process runtime on Bun and Node. The release includes package renames and two intentional API breaks.

## Rename packages

The old package names are a clean break and are not shipped as compatibility stubs.

| 0.4 package | 0.5 replacement |
| --- | --- |
| `@yieldstar/bun-sqlite-runtime` | `@yieldstar/sqlite-runtime` |
| `@yieldstar/bun-worker-invoker` | `@yieldstar/worker-invoker` |
| `@yieldstar/bun-http-server` | `@yieldstar/http-server` |

Remove the old dependencies, install their replacements, and update every import. During the eventual npm release, the old published package names should be marked deprecated with a message pointing to this guide.

## Select a SQLite connector

Runtime classes now come from the package root. The native database factory comes from a host-specific entry point.

```ts
import { SqliteEventLoop, SqliteHeapClient } from "@yieldstar/sqlite-runtime";
import { createSqliteDb } from "@yieldstar/sqlite-runtime/bun";
```

Node applications use the identical runtime surface with:

```ts
import { createSqliteDb } from "@yieldstar/sqlite-runtime/node";
```

The Node connector uses `node:sqlite` `DatabaseSync`; it does not cast or emulate the Bun database API.

## Remove executable mode

Delete the `executable` option from `createWorkflowInvoker`. The invoker now always uses `node:child_process.fork` and advanced IPC serialization.

```ts
const invoker = createWorkflowInvoker({ workerPath, logger });
```

Bun-compiled standalone executables are not supported because their IPC wire format is incompatible with Node's V8 advanced serialization.

The new optional `execPath` selects a different binary from the same runtime family; it is not a cross-runtime bridge. Node parents must fork Node workers and Bun parents must fork Bun workers. The worker sends a `ready` handshake before the invoker delivers an event, and an incompatible or non-listening worker emits an error after `handshakeTimeout` instead of hanging.

## Make store updates synchronous

Store updater and take-claim callbacks must not return promises. Fetch or compute asynchronous inputs before entering the callback.

```ts
const profile = await loadProfile();

await account.update((draft) => {
  draft.profile = profile;
});
```

Callbacks must also be deterministic and side-effect-free because a compare-and-swap conflict can run them again against a newer snapshot.

## Run on Node

Node 22.6 or newer supports TypeScript worker paths through built-in type stripping. On older Node releases, compile workers to JavaScript and pass the compiled file URL as `workerPath`.

HTTP route handlers now use standard `Request` and `Response` types. The returned routes object still plugs into `Bun.serve`, and it can also be adapted to any Request-to-Response router on Node.

## Upgrade checklist

1. Replace all three old package names and imports.
2. Import `createSqliteDb` from `/bun` or `/node` and import shared SQLite clients from the package root.
3. Remove the worker invoker's `executable` option and ensure any `execPath` uses the same runtime family as the parent.
4. Move asynchronous work outside store updater and take-claim callbacks.
5. Use Node 22.6 or newer for TypeScript workers, or point the invoker at compiled JavaScript.
6. Run the application tests under the host runtime and verify persistence against the matching real SQLite connector.
